# kvlite-java 设计决策

| 决策 | 动机 | 可行替代方案 | 代价与局限 |
| --- | --- | --- | --- |
| 1. Memtable 用 `TreeMap` | 直接获得 Java 字符串排序、范围视图和最新版本，flush 可顺序迭代。 | 哈希表加独立排序。 | 点读和写入为 O(log n)，节点有额外内存开销。 |
| 2. 每条 WAL 同步 | 先写并同步，再更新内存，单条成功返回有清晰的进程退出恢复边界。 | 分批 group commit，等一批统一同步。 | 存储同步延迟进入每次写入，持写锁期间拘束其他操作。当前也未验证跨平台目录项断电持久性。 |
| 3. 只修补物理不完整的 WAL 尾帧 | 严格区分截断与完整帧损坏。已完整写入的坏 CRC 报错并保留文件。 | 也截断末条完整坏 CRC 帧，可继续打开数据库。 | 替代方案可能静默丢弃已确认写入。长度反码加 CRC 增加帧开销，部分成对损坏仍可能被判作截断。 |
| 4. memtable 4 MiB 与 WAL 16 MiB 任一到限触发 flush | 反复更新同一 key 时 memtable 不增长，WAL 上限限制重放工作量。 | 只按 memtable 大小触发。 | 热 key 可以产生只有一个 key 的小 SSTable，导致额外读放大。全量 compaction 保留磁盘最新版本并回收旧表。两道阈值都在完成一条写入后检查。 |
| 5. 每 32 条记录采样一次，定位读拆头与 payload | 稀疏索引减少常驻内存，记录头先校验长度，再分配和读 payload。不同读者使用各自偏移。 | 完整索引，或以块为单位读入和解析。 | 每表需要索引 floor 查找及最多一段顺扫。每条有非空 payload 的记录通常要两次定位读，分别获取 9 字节头与 payload。短读可能增加调用，空 payload 无需第二次通道读。逐条读取也增加缓冲分配，块读可减少调用但会预读更多数据。 |
| 6. 原子发布带编号的 manifest | 先写全引用对象，最后让一个最终文件名决定恢复快照。 | 原地重写单个 manifest，或使用独立事务日志。 | 需要本地文件系统支持同目录原子移动，提交后仍可能有旧文件待清理。文件同步和原子移动未建立跨平台的目录项断电持久性保证。 |
| 7. Tombstone 是物理记录 | 在查找、扫描和不完整的版本视图中压住更旧的值。全量磁盘 compaction 消耗该 key 的所有旧磁盘版本后才能丢弃它。 | 立即重写旧表来物理删除，或在磁盘上永远保留删除标记。 | 删除仍需同步 WAL 和占用空间，到下一次全量 compaction 才能回收。 |
| 8. Range scan 与 compaction 共用优先队列 | 每源只保留一条队首，按 key 和来源优先级选胜者。 | 把所有记录收进映射后再排序。 | k 个源、N 条输入需要 O(N log(k+1)) 时间和 O(k) 队列空间，此外有稀疏索引。对外 scan 必须为结果分配空间。 |
| 9. 显式全量磁盘 compaction | 单一规则便于说明何时能丢 tombstone。输出按记录流式写出。 | 增量或分层归并。 | 全部输入表都要读取，存活值会被重写。操作只由调用方触发，无后台调度，且持写锁直到发布与清理完成。 |
| 10. 每实例一把 `ReentrantReadWriteLock` | 读者共享不可变表，写者独占 WAL、memtable、句柄及 manifest 切换。 | 全部用一把互斥锁，或做版本化读快照。 | 允许并行读，但 flush、compaction 和 close 会阻塞同实例其他操作。非公平锁没有先来先服务保证。实例之间没有文件锁。 |

# kvlite-java 版本 1 文件格式

整数采用大端序。偏移从文件或所属结构的第一个字节起算，表格区间右端不含。字符串使用严格 UTF-8，长度以字节数计算。下列布局对应 `EntryCodec`、`Wal`、`SSTableWriter`、`FileSSTableReader` 和 `TableSet` 的实际读写。

## WAL 与 SSTable 共用的记录体

| 起始偏移 | 字节数 | 内容 |
| ---: | ---: | --- |
| 0 | 1 | 类型 `01` 为值，`02` 为 tombstone |
| 1 | 4 | key 长度 K，范围 0–65,536 |
| 5 | 4 | 有符号 value 长度 V，值记录为 0–1,048,576，tombstone 为 `ff ff ff ff` |
| 9 | K | key 的 UTF-8 字节 |
| 9 + K | V 或 0 | 值记录紧跟 V 个 UTF-8 字节，tombstone 无 value 字节 |

固定头共 9 字节，记录体总长为 `9 + K + max(V, 0)`。空值的类型仍为 `01`。解码检查类型、长度、剩余字节数和 UTF-8。字符串顺序采用解码后的 Java `String.compareTo`。

## WAL

文件偏移 0–3 是 `4b 56 57 4c`（`KVWL`），偏移 4–7 是 `00 00 00 01`。从偏移 8 起是零个或多个连续帧。

| 帧内偏移 | 字节数 | 内容 |
| ---: | ---: | --- |
| 0 | 4 | 记录体长度 N，范围 9–1,114,121 |
| 4 | 4 | N 的 32 位逐位反码 |
| 8 | N | 共用记录体 |
| 8 + N | 4 | Java CRC32，覆盖原始 8 字节帧头及 N 字节记录体，按 32 位原样存储 |

每帧占 `12 + N` 字节。写入完整帧后调用 `force(true)`。恢复先验证 WAL 文件头。文件尾的帧头不足 8 字节，或通过帧头校验后发现缺少帧体或校验和时，截到上一完整帧并同步。长度超限、反码有误、完整帧 CRC 不符或记录无效会报错。能够同时骗过长度反码校验的成对损坏仍有误判为尾部截断的可能。

## SSTable

头部偏移 0–3 是 `4b 56 53 54`（`KVST`），偏移 4–7 是 `00 00 00 01`。接下来是 `[8, indexOffset)` 的有序、去重记录体区域，没有 WAL 的帧头和 CRC。索引从 `indexOffset` 开始，到文件最后 24 字节之前。

| 索引条目内偏移 | 字节数 | 内容 |
| ---: | ---: | --- |
| 0 | 4 | key 的 UTF-8 字节数 K |
| 4 | K | key 字节 |
| 4 + K | 8 | 被采样记录的绝对偏移，指向其类型字节 |

第一条记录和之后每 32 条各采样一次（记录序号 0、32、64……）。writer 从偏移 8 累计实际编码长度，不依赖缓冲输出时的通道位置。索引 key、偏移严格递增。

| footer 内偏移 | 字节数 | 内容 |
| ---: | ---: | --- |
| 0 | 8 | 索引绝对起点 `indexOffset` |
| 8 | 4 | 采样数，等于记录数除以 32 向上取整，Java 此字段由非负 `int` 表示 |
| 12 | 8 | 记录数，由非负 `long` 表示 |
| 20 | 4 | `4b 56 46 54`（`KVFT`） |

偏移受非负 `long` 范围约束。空表恰好 32 字节，两个计数为 0，索引起点为 8。打开时核对文件头和 footer、索引边界和顺序、采样指向的记录头及 key。点读、范围读与归并在遍历时解码所访问的记录。没有 SSTable 记录 CRC，按结构校验无法检测所有位翻转。

## Manifest 与发布

UTF-8 文本，无 BOM。首行是 `KVMANIFEST 1`，第二行是活动 WAL 文件名，余下各行各有一个 SSTable 文件名，顺序从新到旧。每行包括最后一行都以 `0a`（LF）结束。文件名格式分别为 `manifest-<19 位正编号>.txt`、`wal-<19 位正编号>.log`、`sst-<19 位正编号>.sst`，编号用 ASCII 十进制补零。禁止重复的表名。两行 manifest 表示没有 SSTable。

每类输出先写同目录 `.tmp` 文件，完成同步并关闭写句柄后以 `ATOMIC_MOVE` 发布。SSTable 缓冲先刷新到通道，再同步通道。编号分配同时考虑已有最终文件和符合规则的临时文件。最高编号的最终 manifest 是打开入口，表的新旧顺序直接由其中的行序决定。Flush 更换活动 WAL，compaction 可在新 manifest 中继续引用同一 WAL。

`EntryCodecTest`、`WalRecoveryTest`、`SSTableTest` 和 `TableSetTest` 分别验证记录字段、WAL 尾部和损坏行为、稀疏索引与 footer、manifest 的恢复选择。
